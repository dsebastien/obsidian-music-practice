# v0.4: chords and scales

Goal: chord and scale notes draw their own diagram from their properties, with no copy in the body (#33, #34), through `@dsebastien/music-notation` 0.3. Tabs and scores move to v0.5.

- Empty `chord` blocks in chord notes and empty `fretboard` / `keyboard` blocks in scale notes draw from the note's properties (configured names, instrument from the note type), through the library's `blockFromProperties`. Property changes redraw them (tracked render children and metadata change events). Blocks with content draw their content.
- Add a learning note fills only the properties: chords from a symbol, a name in words (`A Major`) or frets (`x02220`, recognized); scales with a root, a scale or mode (the type's `scale_type` values) and a shape, with a live preview. The template's block stays empty.
- Command "Identify this chord": fills the chord symbol, root, quality and aliases of a chord note from its frets or pitches; asks when several readings fit.
- Obsidian Publish: `window.musicNotationOptions.properties` in `publish.js` lets empty blocks draw from the page's properties (documented).
- Existing chord notes in the vault: their blocks emptied once both sides draw them (checked in Obsidian and on Publish).
- Docs (Notation, Usage, screenshots), tests, vault checks on throwaway notes, adversarial review, release 0.4.0.

Done: everything above but the release. Left: library 0.3.0 release and dependency bump, adversarial review, release 0.4.0, then `publish.js` (properties) and emptying the existing chord notes' blocks in the vault.
