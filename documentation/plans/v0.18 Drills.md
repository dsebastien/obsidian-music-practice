# v0.18: drills (#73)

Goal: drills that follow what the learner actually learns and show where they miss: notes on the fretboard and the keyboard, chords and scales from their notes (and ones not in their notes yet), with a map of weak spots and drills that focus on them. Extends #44 (closed) and feeds #23 (insights). Status: every decision taken (below); nothing built.

## Decisions (Sébastien, 2026-11-07)

1. First version: all four drill kinds.
    - Fretboard notes: find a note on a string or in a fret range ("find every G on string 5"), and name the note at a marked position; string by string, or a fret range.
    - Chords from the learner's notes: name the chord from its diagram, for chords taken from the guitar and piano chord notes (the ones being learned first).
    - Scales from the learner's notes: find the notes of a scale or position being learned, or name the scale from its shape.
    - Keyboard notes: the same note drills on a piano keyboard.
2. Also chords and scales that are not in the learner's notes yet, with a way to create the missing note from the drill, the way the Kanban Action Planner and Journal Bases create notes: the type's template (Templater), folder and affixes. Music Practice already does this for Add a learning note (`note-creator.service.ts`: the Obsidian Starter Kit type's template rendered without its prompts, its folder, affixes and tags; the standalone model otherwise): reuse it.
3. Answers on the instrument's drawing: a click on the fretboard or the keyboard. Empty positions have no element today (only drawn dots carry `data-mn-string`, `data-mn-fret`, `data-mn-note`), so music-notation needs a clickable layer over every string × fret and every key first: a library release before the plugin work.
4. One drill note per drill: a learning note (an exercise, like the chord change pair notes) with mastery, spaced review and time; its weak-spot map (hits, misses and answer time per note, string and fret) is stored in that note, so it syncs and can be seen.
5. A modal, like the chord change drill: a command and a practice panel button open it; question, drawing, answer, score; Save writes the drill note; the weak-spot map shows there.

## Decisions, second round (Sébastien, 2026-11-08)

6. One drill note per drill kind and setting ("Fretboard notes, string 5, frets 0–5"), each with its own mastery, review and time.
7. The weak-spot map is a compact list property on the drill note (for example `drill_stats` with items such as `s5f3 G: 7/9 1.8s`), queryable by Bases and Dataview; the modal draws it as a heat map.
8. A drill session counts like every practice: the drill note joins the practice panel's list and Log practice logs it with the practice timer's minutes. Save in the drill writes the score, the map and the review only.
9. Weak-spot focus: 6 questions in 10 come from the weakest spots (most misses, slowest answers), the rest at random in the setting's range. A spot stops being weak after 3 right answers in a row, each under 2 s. Both numbers are settings.
10. "Not in my notes yet" covers three sources: chords that the pieces' ```chords charts and progressions use without a chord note; chords and scales that a current-focus note lists as prerequisites or unlocks without a note; and any chord family or scale of the library, picked in the drill.
11. A drill is 20 questions (a setting).
12. By ear is later: issue #91.
13. Every property the drills add (the map, the drill's kind and setting) must exist in the vault's note types: add it to the note types through the Obsidian Starter Kit plugin API (`osk-vault-plugin-api`), add its name to Music Practice's property-name settings, and document it in the Obsidian Starter Kit user guide in the vault (`Obsidian Starter Kit - System - Music Learning System` and the note type pages it links). Same rule as for every property the plugin writes: nothing in a note that the system doesn't define.

14. Drill notes use the existing guitar and piano exercise types (as the chord change pair notes do): new properties on those types, no new folder or template (Sébastien, 2026-11-08).
15. Three new properties, names configurable in Music Practice's property-name settings: `drill_kind` (fretboard notes, keyboard notes, chord names, scale shapes), `drill_setting` (text: "string 5, frets 0-5", "7th chords, from my pieces") and `drill_stats` (the weak-spot list). Note name: `<Kind>, <setting> (Guitar Exercise)` (the type's affixes from the Starter Kit), for example "Fretboard notes, string 5, frets 0-5 (Guitar Exercise)". Rule 13 applies to all three: the exercise types in the vault and the user guide get them before the plugin writes them.

No open question left.

## Build (how the decisions become code)

- Library: music-notation 0.15.0 (pick layer, sound on picks), exact pin.
- Property names in Settings → Property names: `drillKind` (`drill_kind`), `drillSetting` (`drill_setting`), `drillStats` (`drill_stats`). Written only when the exercise type defines them; Save says which one is missing otherwise.
- `drill_kind` values (the vault's allowed values): `Fretboard notes`, `Keyboard notes`, `Chord names`, `Scale shapes`. Guitar exercise type for fretboard, chord and scale drills on guitar; piano exercise type for keyboard drills and piano chords and scales.
- Domain `src/app/domain/note-drill.ts` (pure, specs first):
    - Settings and their words: fretboard `{ strings, frets, ask }` ("string 5, frets 0-5", "strings 1-6, frets 0-12"); keyboard `{ keys, ask }` ("keys C3-B4"); chords `{ instrument, source, family? }` ("7th chords, from my notes"); scales `{ instrument, source }` ("from my notes"). `ask`: find, name, or both (each question picks one). The words are the `drill_setting` value and, with the kind, the note's title: `<Kind>, <setting>`.
    - Spots (the map's keys): `s5f3` (string 5, fret 3) on fretboards, `F#4` on keyboards, the chord symbol, the scale name. Map item: `<spot> <answer>: <right>/<asked> <avg>s`, plus `, <n> in a row` while a streak of right answers under the fast time runs (`s5f3 C: 7/9 1.8s, 2 in a row`). Unknown items are kept as written.
    - Weak spot: asked, and not (3 right in a row, each under 2 s): both numbers are settings (`drillClearStreak`, `drillFastSeconds`). Weakest first: most misses, then slowest.
    - Questions: 20 (setting `drillQuestions`); 6 in 10 (setting `drillWeakShare`, 60 %) from the weak spots of the drill note's map (weakest first, cycled), the others at random in the setting's range, no spot twice in a row. Deterministic with a seeded random (specs).
    - Fretboard find: "Find C on string 5" (the spot's string; any fret of that note on it in the range is right). Fretboard name: a dot at the spot, no label; answer with the 12 note buttons (sharps; flats read as the same note). Keyboard find: "Find F#4" (that key); name: the key lit without label, the 12 note buttons.
    - Chord names: the chord's diagram (its note's frets or pitches; a library chord's easiest voicing), 4 choices (the right one and 3 others from the pool, same root first). Scale shapes: name the scale from its shape (its notes on a fretboard or keyboard, no labels; 4 choices), or find its notes ("Find the notes of A minor pentatonic": click each one on the drawing, in its range; right when every note is found, each wrong click a miss).
    - Pools ("not in my notes yet", decision 10): from my notes (chord and scale notes of the instrument, being learned first: focus, then learning, then all); from my pieces (chords that the pieces' ```chords charts and progressions use without a chord note); from my focus (prerequisites and unlocks of current-focus notes that lead to no note); from the library (a chord family or every scale type, picked in the drill).
    - Scoring: right answers out of the questions, average time of the right ones. Review: 90 % or more good, 60 % or more shaky, else failed (the light SM-2 of `review.ts`).
- Service `src/app/services/note-drill.service.ts`: the pools from the vault, the drill note (found by type, kind and setting; created on first Save through the note creator with the type's template, level Learning), Save (one `processFrontMatter`: kind, setting, merged map, review fields), Create note for a missing chord or scale (the type's template; title as Add a learning note names it).
- Modal `src/app/ui/note-drill-modal.ts`: pick the kind and setting (or start from a drill note), questions one at a time (the drawing with the pick layer and sound, or the choice buttons; right or wrong shown at once, the right place marked after a miss; Enter or a click moves on), the score and the heat map (each spot colored by its right share, slow ones marked), Save, Log this drill (opens Log practice with the drill note, like the chord change drill), Again. Its note joins the practice panel's list when the drill starts (decision 8); the timer is the user's.
- Commands: `Drill notes, chords or scales` (`note-drill`) and `Drill notes, chords or scales for the current note` (`note-drill-current`, on a drill note: its kind and setting). Practice panel: the Drill button opens a menu: Chord changes (as before), Notes, chords and scales.
