# v0.18: drills (#73)

Goal: drills that follow what the learner actually learns and show where they miss: notes on the fretboard and the keyboard, chords and scales from their notes (and ones not in their notes yet), with a map of weak spots and drills that focus on them. Extends #44 (closed) and feeds #23 (insights). Status: decisions taken (below); open questions listed; nothing built.

## Decisions (Sébastien, 2026-11-07)

1. First version: all four drill kinds.
    - Fretboard notes: find a note on a string or in a fret range ("find every G on string 5"), and name the note at a marked position; string by string, or a fret range.
    - Chords from the learner's notes: name the chord from its diagram, for chords taken from the guitar and piano chord notes (the ones being learned first).
    - Scales from the learner's notes: find the notes of a scale or position being learned, or name the scale from its shape.
    - Keyboard notes: the same note drills on a piano keyboard.
2. Also chords and scales that are not in the learner's notes yet, with a way to create the missing note from the drill, the way the Kanban Action Planner and Journal Bases create notes: the type's template (Templater), folder and affixes. Music Practice already does this for Add a learning note (`note-creator.service.ts`: the Obsidian Starter Kit type's template rendered without its prompts, its folder, affixes and tags; the standalone model otherwise): reuse it.
3. Answers on the instrument's drawing: a click on the fretboard or the keyboard. Empty positions have no element today (only drawn dots carry `data-mn-string`, `data-mn-fret`, `data-mn-note`), so music-notation needs a clickable layer over every string × fret and every key first: a library release before the plugin work.
4. One drill note per drill: a learning note (an exercise, like the chord change pair notes) with mastery, spaced review and time; its weak-spot map (hits, misses and answer time per note, string and fret) is stored in that note, so it syncs and can be seen.
5. A modal, like the chord change drill: a command and a practice panel button open it; question, drawing, answer, score; Save writes the drill note; the weak-spot map shows there.

## Open questions (ask before building)

- Drill notes: one per drill kind and instrument ("Fretboard notes (Guitar Exercise)"), or one per drill setting (string 5, frets 0–5)? Which note type: the existing guitar/piano exercise types, or a new drill type in the Starter Kit?
- Weak-spot map format in the note: a compact property (for example `drill_stats` as `"E5f3: 7/9 1.8s"` items), or a table in a section the plugin owns? Properties stay queryable by Bases; a table is easier to read.
- How a drill session counts: a Log practice of the drill note with the timer's minutes (as every practice), or the drill's own time written on Save?
- Weak-spot focus: how many questions come from weak spots (for example 60 %), and when a spot stops being weak (for example 3 right answers in a row under 2 s)?
- Scales "not in my notes": from which list (the library's scales and positions) and how to pick them (the current key or focus, a chosen scale)?
- Chords "not in my notes": which chords (the library's chord list by family, those in the learner's pieces' charts, the next ones a skill tree suggests)?
- By ear (#31 playback): later, or in this version (play a note, find it)?
- Timing: a fixed number of questions (20), a time box (2 min), or until stopped?

## Library work first (music-notation)

- A click layer on fretboards and keyboards: every string × fret position and every key is a target with its string, fret and note, keyboard reachable (arrows move between positions, Space or Enter answers), drawn above the dots, off by default (a render option), with marks for right and wrong answers.
- Released and pinned before the plugin's drill modal uses it.
