# v0.22 Save diagrams as images (#51)

Status: shipped in 0.22.0.

## Goal

Keep a diagram, or a whole block, as a file in the vault: a PNG or an SVG to print, put on a slide or share. Copying to the clipboard is the library's (Copy as image on the block bar, music-notation 0.19); this saves files.

## Decisions (Sébastien, 2026-11-10)

1. A right-click on a drawn notation block offers to save the diagram under the pointer, or the whole block, as PNG or SVG.
2. The folder is configurable: Obsidian's attachment location for the note by default, or a vault folder of your choice.
3. Optionally, a link to the new file goes into the note, right after the block. Off by default.

## Rules

- **Where**: the block languages the plugin draws with the library: `chord`, `chords`, `keyboard`, `fretboard`, `strum`, `picking`, `progression`, `circle`. Not `tab` and `score` (alphaTab draws them; the library's export leaves them out) and not `playalong`. Reading view, live preview and embeds; the menu is Obsidian's `Menu` (`showAtMouseEvent`), so a long-press that fires `contextmenu` on mobile opens it too. The menu replaces the browser's and Obsidian's own menu on the block (`preventDefault`, `stopPropagation`). It works with playback off: the menu doesn't depend on the bars.
- **Menu items**:
    - Over a diagram (a `svg.mn-svg` outside the bars): "Save diagram as PNG" and "Save diagram as SVG". The diagram's image is its captioned figure (`figure.mn-captioned`) when it has one, else its playable wrapper (`.mn-playable`), else the drawing: title and captions included, as the library's Copy as image does.
    - "Save block as PNG" and "Save block as SVG" when the pointer is not over a diagram, or when the block has more than one diagram. The block's image is the block element (`.mn-block`, else the block's container), bars left out by the library's export.
    - Nothing when the block drew nothing (an error, an empty block): the browser's own menu shows.
- **Image**: PNG through the library's `toPng` (scale 2, the page's colors on the page's background, as Copy as image); SVG through `toSvgString` (standalone, styles inlined, the page's colors, transparent).
- **File name**: `<note name> - <what>.png|svg`. `<what>` is the diagram's visible title (`text.mn-title`), else its accessible name (its `<title>`), else "Diagram"; for a block, the titles of its diagrams joined by ", " (3 at most, then "…"), else the language ("chords block"). Made safe for every system: `#`/`♯` after a note letter is " Sharp", `♭` is " Flat" (as drill note names spell sharps); `\ / : * ? " < > | # ^ [ ]` and control characters become spaces; spaces collapsed; at most 120 characters; never empty ("Diagram"). In a canvas (no note name), the canvas file's name.
- **Folder** (`diagramImages.folder`): empty (default) = Obsidian's attachment location for the note (`fileManager.getAvailablePathForAttachment`, which also dedupes and creates the folder). Otherwise a vault folder: backslashes read as `/`, leading and trailing slashes dropped, created when missing (with its parents), the name deduped as Obsidian does (`name.png`, `name 1.png`, `name 2.png`, …). Validation refuses `..` and `.` segments, a drive (`C:`), and `* ? " < > | :` in a segment; the error says what to write.
- **After saving**: a notice "Saved <path>". With **Embed saved images** (`diagramImages.embed`, off by default), the link (`!` + `fileManager.generateMarkdownLink`, so wikilink or Markdown as the vault is set) goes on its own line right after the block's closing fence, through `vault.process`. Only when the block is still where it was drawn: the note's lines from the section's start to its end must equal the section's text and the last one must be a fence; otherwise, and in a canvas, the note is left unchanged and the notice says the link wasn't added. Nothing else in the note changes.
- **Errors**: an image that can't be made or written: a notice says so ("Couldn't save the image: …").

## Build

1. Domain `src/app/domain/diagram-images.ts` (pure, specs first): `imageFileName`, `blockImageName`, `parseImageFolder` (validation and normal form), `numberedPath` (dedupe in a folder), `withEmbedAfter` (the note text with the link after the block, or null).
2. Settings: `diagramImages: { folder: '', embed: false }`; `parseSetting` validates the folder; loading drops wrong types. Settings → Notation blocks: "Diagram images folder" (text), "Embed saved images" (toggle).
3. `NotationBlocks` takes an optional menu hook, called on `contextmenu` of each library-drawn block with the block's element, language, note path and a lazy section reader.
4. Service `src/app/services/diagram-images.service.ts`: the menu (Obsidian `Menu`), the image, the path, the write, the notice, the embed.
5. Docs: `docs/notation.md`, `docs/configuration.md`, README, Business Rules, `NEXT_RELEASE.md`, history.
