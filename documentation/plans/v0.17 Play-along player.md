# v0.17: play-along player (#75)

Goal: practice a song with its recording: loop a passage, slow it down without changing its pitch, jump to sections, and start each pass after a count-in. Local audio files first. Status: being built on the branch `play-along` (see "Build", which is the requirement where it is more precise than the sections above).

## What the learner does

1. In a piece note, link or embed the recording (an audio file in the vault: mp3, m4a, ogg, wav, flac, webm).
2. Open the player for it. It shows a waveform-free timeline (a bar with the playhead, the A and B marks and the sections), play / pause, the time, the speed and the loop.
3. Set A and B (buttons "Set A" and "Set B" at the playhead, or drag the marks; keyboard: `[` and `]`), turn on loop: the passage plays again and again.
4. Slow it down: 50 % to 100 % (and up to 125 %), in steps of 5 %, the pitch kept.
5. Jump to a section ("Verse", "Chorus", "Solo") from its marker; a marker can also become the A-B loop.
6. With count-in on, each pass (or only the first) starts after one bar of clicks at the piece's tempo, scaled by the speed.

## How it works (proposed)

- Playback: an `HTMLAudioElement` in the note's window (popouts have their own), `preservesPitch = true` (Chromium's time stretch; good from about 50 % up), `playbackRate` for the speed, the file through `app.vault.getResourcePath(file)`. No new dependency, nothing downloaded.
- A-B loop: the playhead is read on each animation frame (about 16 ms), not on `timeupdate` (250 ms, too late for a loop); at B it seeks to A (minus a small pre-roll, 0.2 s by default), or waits for the count-in first.
- Count-in: the metronome service's clicks (its volume and sound), `beats` clicks at `tempo × speed`, the meter from `time_signature`; the tempo from the note's `bpm_target`, else `bpm_current`, else a tap tempo on the player.
- Speed trainer (optional, like the backing loop's): start at a lower speed and raise it by a step every N passes up to 100 %.
- Practice time: playing counts toward the item's practice timer like the other players (the session note rules of 0.13).
- Save BPM: offers the tempo reached (`tempo × speed`) as the note's `bpm_current`, as the tab and pattern bars do.
- Mobile: the same element; keyboard shortcuts only on desktop.

## Specs to write first

- A-B: setting, swapping when B is before A, clearing, seek at B with the pre-roll, a loop that survives a speed change and a seek by the user.
- Speed: clamping, steps, `preservesPitch` set, the count-in tempo scaled.
- Markers: parsing (open question 2), ordering, a marker as a loop, a malformed line's message.
- Count-in: first pass only or each pass; the meter and tempo sources and their fallbacks.
- Lifecycle: the player stops and frees the element when its note closes, the plugin unloads, or the block is redrawn (the 0.15 single-instance rules).

## Decisions (Sébastien, 2026-11-05)

1. The player is a code block in the piece note: ` ```playalong ` with the file and its sections, one player per recording, in reading view and live preview.
2. Section markers are lines in the block (`0:12 Verse`); a marker set in the player is written back as a line.
3. The count-in plays before every pass of the A-B loop; when the note has no `bpm_target` or `bpm_current`, a Tap button sets the tempo.
4. The first version plays local audio and video files from the vault (the same media element plays mp4 and webm). YouTube stays a separate decision.

## Build (2026-11-07)

What the build does, from the decisions. Where it differs from "What the learner does" and "How it works", this section wins.

Block:

````
```playalong
file: [[Wonderwall.mp3]]
0:00 Intro
0:12 Verse
0:45.5 Chorus
```
````

- The recording: a `file:` line, or a line that is only a link (`[[x.mp3]]`, `![[x.mp3]]`, `[x](x.mp3)` or a plain path), resolved from the note like any link. Audio: mp3, m4a, wav, flac, ogg, oga, opus, 3gp, aac (and webm); video: mp4, webm, ogv, mov, mkv, m4v (Obsidian's own media types). A webm is played as a video (its picture shows when it has one).
- A section: `<time> <name>`, time `m:ss`, `mm:ss` or `h:mm:ss`, with up to three decimals (`0:45.5`); the name may be empty (the time shows instead). Sections are shown in time order. Any other line: a message under the player naming its line ("Line 4 is not a section: write 0:12 Verse"); the rest works.
- No file, a file not in the vault, or a type not listed: a message in place of the player, the block text below it.
- The language: `playalong`, a toggle in Settings → Play-along (on by default; off shows the block as code), left alone when another plugin has it (as the notation blocks). Not part of `notation.registered` (the 10 notation languages).

Player:

- An `<audio>` (hidden) or `<video>` (shown, a click on it plays or pauses) made in the block's document (popouts), no native controls, `preload="metadata"`, `preservesPitch` on, `playbackRate` = speed.
- Controls: Play/Pause, the time (`0:12.3 / 3:45`), a timeline (a slider, step 0.1 s) with the A-B span and the sections drawn on it; speed − and + (50 % to 125 %, steps of 5 %, 100 % at start); Set A, Set B, Loop (on/off), Clear; Count-in (on/off, on at start); the tempo and its source, or Tap; Add section; Save BPM (learning notes only). The sections as a row of buttons: a click jumps there, its loop button loops it (from its time to the next section's, the last to the end).
- Marks are set at the playhead (buttons or keys); dragging them is left out. Set A after B (or B before A) swaps them; a loop shorter than 0.5 s is refused (a notice). Set B with an A turns the loop on. Clear removes both and turns the loop off. Loop needs A and B.
- Keyboard, when the player has the focus: Space or K play/pause, `[` Set A, `]` Set B, L loop, ← and → 5 s (Shift: 1 s), − and + speed, C count-in, T tap, M add section. Every control is a button or the slider, so Tab reaches each one.

Loop and count-in:

- On each animation frame of the block's window, and on `timeupdate` and `ended` (rAF stops in a hidden window): with the loop on, a playhead at or past B (or the end) wraps: pause, seek to `max(0, A − pre-roll)`, count-in when on, then play. A seek by the user past B wraps at once; a seek before A plays on into the loop. A speed change keeps the loop.
- Pre-roll: Settings → Play-along → Pre-roll, 0 to 2 s (0.2 by default).
- The count-in plays before Play and before every pass of the loop, when Count-in is on and a tempo is known: the metronome's count-in bars (at least 1) of beats, beats per bar from the note's `time_signature` as the metronome counts it (6/8: 2 dotted beats), else 4; at tempo × speed; the metronome's clicks and volume (first beat accented), scheduled on its audio clock. The recording starts so that the passage's start (A, or where Play was pressed) sounds on the beat after the last click: it starts playing at `max(0, start − pre-roll)` that long before. Pause cancels a count-in.
- Tempo (Sébastien, 2026-11-07, replaces decision 3's `bpm_current` fallback: `bpm_current` is the tempo the learner plays at, so the count-in clicked too slow and each Save BPM could lower it again): the block's `tempo: <BPM>` line (20–300) is the recording's tempo at 100 %; else a tempo tapped on the player (2 taps or more, the metronome's tap rule, heard at the current speed, stored as tapped ÷ speed), which is written as the block's `tempo:` line 2 s after the last tap (in place, else after the file line); else the note's `bpm_target`. `bpm_current` is never used. Shown as `87 BPM (tempo line)`, `(tapped)`, `(target)`; Tap always shows. Without a tempo, Count-in says "Tap the tempo first" and plays none.

Practice:

- Play adds the note to the practice panel's list when it is a learning note not in the list (Sébastien, 2026-11-07); the timer does not start by itself. The minutes come from the practice timer, as for every other practice.
- Save BPM (learning notes, tempo known): Set BPM with round(tempo × speed) as the current BPM, the same flow as the other bars.
- One player plays at a time: Play pauses every other play-along player, stops the metronome and the backing loop; the metronome or the backing loop starting pauses the play-along players.

Sections written back:

- Add section (at the playhead, rounded to 0.1 s) asks for its name (a modal, "Section 3" proposed) and writes `<time> <name>` into the block: before the first section that comes later, else after the last section line, else after the file line. Through the note's editor when it shows the note in editing view (one transaction, Ctrl+Z undoes it), else the file; the block is found as Keep this view finds it (#83). A block that changed meanwhile: a notice, nothing written.

Lifecycle and state:

- Freed (paused, `src` removed, `load()`, element removed, frame loop and count-in cancelled) when Obsidian unloads the block (a redraw, the note closed), on a layout change when no leaf shows its note any more, when its window closes, and when the plugin unloads. Moved to another window: made again there, with its state.
- A player's state (speed, A, B, loop, count-in, tapped tempo, position) is kept per note and file in memory, until the plugin unloads: the block drawn again (a section written, the note opened again) starts from it. It plays on after a redraw only when its own write caused it (Add section), within 5 s.

Specs written first: the block parser and its messages, times, the file types, section ordering and insertion, A-B (set, swap, too short, clear, wrap with the pre-roll, seek past B, a speed change), speed (clamp, steps), count-in (bars, meter, tempo × speed, start offset, no tempo), the tempo source and tap, Save BPM's tempo, the panel rule, the service's lifecycle (freed on unload, redraw, note closed, plugin unload; state kept; one plays at a time; metronome and backing).
