## Sound pack: GeneralUser GS as an optional download (#100)

- The library plays one soundfont per instrument since 0.20.0 (`assets.instruments`, its `generaluser` engine) and takes the app's players by engine since 0.23.0 (`play.engines`, `play.engine`, `TabOptions.engine`). The plugin now gives it the files.
- The pack: the `generaluser` folder of `@dsebastien/music-notation-sounds` 0.1.1, from jsDelivr at that fixed release: 128 program files, the kit, the click, `index.json`, `LICENSE.txt`. 132 files, 14,897,592 bytes. `report.json` (the maintainers' loudness measures) is left out.
- Decisions:
    - One download of the whole pack on a click, no file fetched later on demand: after the click the plugin never touches the network again, and works offline with the pack.
    - Per-file download with `requestUrl` (4 at a time), not one archive: a percent to show, a download that goes on from where it stopped, a few hundred KB in memory at most.
    - The file list with sizes and SHA-256 is in the plugin's source (`src/app/domain/sound-pack.manifest.ts`), written by `scripts/sound-pack-manifest.ts 0.1.1` from the npm tarball (checked against the registry's sha512). The hashes equal the ones jsDelivr's API gives for the same release.
    - The sounds package is not a dependency. A first try as a dev dependency was refused by the install's minimum release age (3 days; the package is from 2026-11-15), which stays as it is. Hashing the tarball's bytes in a script needs no install.
    - The pack's state is read from its folder (`pack.json`, written last), never from the settings: data.json syncs, the files may not.
    - Stored engine values: `generaluser` is new; `soundfont` stays and means the built-in sonivox soundfont (the library's `sonivox`). No migration.
    - A finished download sets Sound to the pack; Remove sets it back to the built-in soundfont.
    - Diagrams play the pack through alphaTab (`createSoundfontPlayer` with `assets.instruments`), not through the library's sample player: one audio path for tabs and diagrams, already checked in Obsidian, with alphaTab's own Ogg Vorbis decoder (the sample player's use of the browser's decoder is unchecked on iOS).
- Code: `domain/sound-pack.ts` (+ manifest), `services/sound-pack.service.ts`, `AlphaTabRuntime` (`setInstruments`, `hasInstruments`, `player(win, engine)`, one hidden player per engine), `playOptions` (engines), `NotationBlocks.redrawTabs`, `TabHost.engine`, the plugin's `engines()`, `enginePlayer()` and `soundPackChanged()`, the settings row (`renderSoundPack`), texts in English and French.
- Not done from the ticket: "Use my own soundfont" (an SF2 or SF3 file of the vault). The "Done when" of the ticket doesn't ask for it.
- Changed on the way: a block's `engine:` line now works in the plugin (before, the plugin passed `player`, and the line changed nothing); tabs and scores are drawn again when Sound changes.
- Checked outside Obsidian, with the service as it is and the real network (a Bun script, a temporary folder as the vault): 132 requests, 2.0 s, every hash right, state `installed`, 14,897,592 bytes plus the marker; `index.json` read back says GeneralUser GS 2.0.3 and `p025.sf3` is a RIFF `sfbk` file; a second download asked for nothing; one damaged file was asked for alone; Remove left no `sounds` folder.
- `tsc`, `lint`, `test` (971 pass), `build` pass. `main.js`: 4,469,390 to 4,493,904 bytes (+24.5 KB: the list of hashes, the texts, the service).
- Not checked: Obsidian itself. To try in a vault: the row in Settings → Playback (texts, the percent, Cancel, Remove, in English and French), a download through `requestUrl` and the vault's adapter, the sound of a chord and of a tab before and after, Remove while a tab plays, a popout window, a phone (the size line, the download, the sound).

## Identify this chord reads the note's name (#119)

- Asked by a user (#119): the chord is typed twice, in the file name and in the properties. Add a learning note already takes it once; a note made from a template (Templater, the Starter Kit) had no help. Sébastien chose the direction name to properties, on demand, with no rename of a note from its properties.
- Identify this chord, on a chord note without frets and pitches, now reads the note's name: "A Minor 7 - Open" gives the symbol, root, quality, alias and the shape. `domain/chord-name.ts` (`titleOfName`, `readChordName`) and its spec; `namedNoteChanges` takes a `shape`; one new text in English and French (`plugin.identify.namedFromName`).
- Decisions:
    - The name is read only when the note has no frets and no pitches. Frets win, as before, and frets that name no chord still open the click modal.
    - The shape is written only when the type defines it and the note has none; a shape in the properties stays.
    - A shape in brackets counts only when the type lists it, so "E 5 (Power)" (a quality's own words) gives no shape.
    - A root stuck to its quality is read ("AMinor 7", "C#Minor"): the ticket's template joins them.
    - A name that says no chord changes nothing: the click modal opens as before.
- `tsc`, `lint`, `test` (985 pass), `build`, `rules:check` pass.
- Tried in Sébastien's vault (Obsidian 1.15.0, Linux) with the branch build, through the Obsidian CLI, on four throwaway guitar chord notes (made, tried, deleted; the release files put back after): "G Flat Minor 7 flat 5 - Shell" got Gbm7b5, Gb, Minor 7 flat 5, the alias and Shell, with the notice "From the note's name: this chord is G Flat Minor 7 flat 5 (Gbm7b5)."; "G Flat Minor 7 - E shape" with `shape: Open` kept Open; "Zz Not A Chord" opened the click modal and wrote nothing; "G Flat Major - Open" with frets x02210 became Am from its frets, no shape written. A second run on a named note gave the "Already named" notice.
