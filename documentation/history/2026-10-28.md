## Adversarial review (before 0.1.0)

15 findings, all addressed:

- Logging checks everything before its first write, writes session → items → activity, runs one at a time; the modal can't submit twice and opens once.
- Item updates are computed from each note's current frontmatter (the cache lags behind back-to-back writes).
- Kanban Action Planner timer: offered only when it runs on the log's activity; not adopting it refuses the log; adoption checks the stop command and waits for KAP's entry (never adds a second one).
- Activity writes are lossless (unknown entries kept, non-numeric minutes left alone), review dates never move back.
- Plan: fun picks before focus, blocks under the per-item minimum are skipped, blocks always add up.
- API: request validation, model rebuilt per call, `typeId`, `startTimer` rejects when running, services private.
- Instrument-less items choose their session type; one log = one instrument.
- Activity lookup by session date and exact (or activity-tagged) name.
- Tags: text values, case-insensitive, most specific type wins; standalone domains setting.
- Cached item index, invalidated by vault events; palette checks are cheap.
- Timer: start day kept, long-run warning, external settings changes reloaded.
- Settings: positive minimums, whole numbers, non-empty unique property names, cross-checks on load.
- Creation applies level effects; shapes cleaned before names; accessibility (link targets, labels, aria-pressed); docs aligned.
  Verified in the vault: timer guard refusal, concurrent log refusal, KAP timer adoption without a duplicate entry.
