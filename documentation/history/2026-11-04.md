## Session types and item time (vault engine parity)

Branch `feat/session-rules`. The vault engine (`osk-learning-shared/scripts/learning.ts`) already applied these rules; the plugin now matches it.

- Which activity: the active activity whose `session_types` lists the session type's note type name (`SessionType.typeName`: OSK slug, else `noteTypeSlug(name)`, the Starter Kit's own slug rule; standalone `<subject>-practice-sessions`). Listed by two: neither. Activities: OSK activities type (slug `activities`, else tagged `type/activity`) inside its folder; standalone: tagged `type/activity` anywhere. Old fallbacks (latest session's link, "Learn {subject}") only without OSK and with no `session_types` value in any note. Otherwise Log practice asks (existing activity: maps and moves the type; new: created on Log practice with the OSK type, template, affixes, tags and first active status; none: remembered as the first offer until reload). `ActivityService` (new). API: `LogRequest.activity` (name/path or null); unmapped → no activity + warning.
- Session notes get `practiced_minutes` (`"<min> [[<note>]]"`, the even split) when the type defines it (standalone session types do). Session note written before the items. A run again (same type tag, date, minutes, items, start time when given) reuses the note, writes nothing on it, does not count a review recorded that day again; its undo keeps the note (`UndoRecord.reused`).
- Item `time_spent` recomputed from the session notes linking to it (`domain/item-time`), in the item's one write, after waiting for the link index; never added to, never lowered (warning), a non-number left alone (warning).
- Activity time: never lowered on its own (`planActivityTime` → `decision`); a notice with Keep (`Manual adjustment` entry from local midnight of `created`, ISO UTC like the engine) / Drop; the choice merges into the last log's undo record (`mergeChanges`).
- Settings: `fields.practicedMinutes` (`practiced_minutes`), `fields.sessionTypes` (`session_types`).
- Tests: domain specs for each rule (engine edge cases: even share with remainder on the first listed, entries summed, unresolved links skipped, conflicts, archived activities, rerun matching), and a whole-log spec on an in-memory vault (`services/test-vault.ts`).
- Deliberate differences from the engine: an item `time_spent` that isn't a number is left alone (the engine overwrites it); a `created` date without time is read as a local day; activities must carry the activity tag (the engine reads every note in the folder).
- Open: needs a vault check (the question in Log practice, a created activity's folder and template, the Keep/Drop notice). Adopting a Kanban Action Planner timer whose entry is a minute longer than the logged minutes now asks Keep/Drop for that minute (the engine does the same).
