## Imports: #62, #64, #66

- #62: block placement moved to `domain/block-placement.ts`. `insertBlock` reads the metadata cache's `sections` (`yaml`, `code`, `math`, `html` sealed; in `list`, `callout`, `blockquote`, footnote sections the fences are scanned within that section only). `sectionsMatch` checks the map against the editor's text (each section's line and column give its offset, nothing but blank lines after the last); when it doesn't match, the line scan (`regionEnd`) stands in. The scan now also strips list markers in front of a fence (`- > ```js`). A code section whose fence is never closed gets the block before it. The properties are always guarded by the scan, whether or not the map lists them.
- #64: `decodeText`: UTF-8 when valid and readable (at most 1%, or one, controls other than tabs and line breaks, unassigned or private-use characters), else UTF-16 LE/BE without a BOM when valid, readable and holding ASCII (chord names, spaces, line breaks: every ASCII character needs a NUL byte, so bytes misread as UTF-16 rarely have any), fewer unreadable then more ASCII wins; else Windows-1252 when readable; else an error ("its text can't be read …") shown in the import notice. Specs: Cyrillic (with chords and lyrics only), Greek, Chinese, Japanese, Latin, LE and BE, all without a BOM; a binary file and a PNG header refused. The old NUL-ratio check failed Cyrillic and Greek.
- #66: a new import note gets the block in its first empty block of the same kind (`tab`/`score` for scores and tabs, `chords` for charts; `placeInNote`), else at the end, instead of under the title. In editing view, a cursor in an empty block of the same kind fills it (`emptyBlockAt`, checked against the section map when it matches); elsewhere the block still goes at the cursor. Insert a tab block never fills. Only blocks at the margin count (not in callouts or lists).
- `insertBlock` takes a `BlockEditor` (a `Pick` of `Editor`), so specs drive it with a fake editor. 350 tests.
- Not checked in Obsidian (no live vault for agents): the section map's real shapes (does `sections` list the frontmatter as `yaml`, `$$` math as `math`; offsets with CRLF notes), and the arrangement template's empty blocks.
- Open: should an import in editing view fill the note's first empty block of its kind even when the cursor is elsewhere (as the osk-music-import skill does for any note)? Kept at the cursor for now. Tables could be sealed too (a block inside a table splits it); not in the issue.
